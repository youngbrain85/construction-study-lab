# 3D 랩실 — 마우스로 시점 돌리기 설계 스펙

- 날짜: 2026-09-07 / 상태: 사용자 승인(범위: **랩실 화면만**)
- 대상: `site/labs/` 3D 랩실 (`site/labs/room/layout.js`, `lab-room.js`)
- 요청: "Lab 3D 화면에서 마우스 컨트롤이 되도록 할 수 있어?"

## 1. 지금 상태와 가능성

랩실은 고정 3/4 부감입니다. 원래 스펙이 "orbit 없음(부가 조작은 범위 제외)"으로 잘라둔 부분입니다. 그런데 지금 구조가 이미 이 기능을 받을 준비가 되어 있습니다.

| 이미 있는 것 | 그래서 |
|---|---|
| `fitCamera(aspect, opts)` — yaw·pitch·fov에서 카메라 위치를 구하는 순수 함수(닫힌식 + 재중심 3회) | 각도를 인자로 받게만 하면 회전이 끝난다. node로 검증 가능 |
| `placeLabels()`가 **매 프레임** 라벨을 재투영 | 시점을 돌려도 라벨이 따라온다. 손댈 곳 없음 |
| 클릭 핸들러의 **8 px 드래그 임계값** | 끌면 회전, 그냥 누르면 스테이션 이동이 이미 구분된다 |
| `markInput()` — 유휴 20 s 정지 해제 + reduced-motion이면 `renderOnce()` | 회전 입력을 여기에 물리면 루프·정지·저모션 경로가 한 번에 해결된다 |
| `keyAt()`가 현재 카메라로 레이캐스트 | 돌린 상태에서도 호버가 맞는다 |
| `stepDolly`가 `camera.position.clone()`에서 출발 | 돌린 시점에서 스테이션을 눌러도 돌리 연출이 자연스럽다 |

새 벤더 파일(three.js `OrbitControls`)은 쓰지 않습니다. 필요한 것은 각도 두 개와 거리 배율 하나뿐이라, 자체 구현이 더 작고 기존 순수 함수·테스트와 맞물립니다.

## 2. 조작

| 입력 | 동작 |
|---|---|
| 왼쪽 버튼 드래그 | 좌우 = yaw, 상하 = pitch. 감도 yaw 0.25 °/px, pitch 0.2 °/px. 위로 끌면 위에서 내려다보는 각이 커진다 |
| 휠 | 줌. 한 노치당 배율 1.1 |
| 더블클릭 · Esc | 기본 시점으로 복귀 |
| 터치 한 손가락 드래그 | 회전(뷰포트에 `touch-action:none`. 랩 페이지는 한 화면이라 스크롤을 뺏지 않는다) |
| 라벨 위 | 회전하지 않는다 — 라벨은 자기 클릭·포커스 핸들러가 처리 |

스테이션 클릭·호버·키보드 이동은 그대로입니다. 돌리 연출(450 ms) 중에는 회전 입력을 무시합니다.

## 3. 각도 제한 — 방이 두 벽뿐이라는 사실에서 나온다

`buildRoomShell`은 **북(z-min)·서(x-min) 두 벽만** 세웁니다. 남쪽과 동쪽은 열려 있고, 기본 시점(landscape yaw 35°, portrait yaw 80°)이 그 열린 남동 사분면에 있습니다. 그 사분면을 벗어나면 벽이 카메라와 방 사이에 들어와 화면이 막힙니다.

- **yaw 0°–90°**: 0°는 정남(+z), 90°는 정동(+x). 두 끝에서도 벽은 화면 가장자리의 배경으로 남고 시야를 가리지 않는다. 밖으로 나가면 벽 뒷면을 보게 되므로 여기서 자른다.
- **pitch 15°–80°**: 15°보다 낮으면 눈높이에 가까워져 앞쪽 소품이 뒤를 다 가리고, 80°를 넘으면 평면도가 된다.
- **zoom 0.85–2.2**: 1.0이 지금의 "방 전체가 들어오는" 거리. 0.85는 약간 여유 있게 물러난 상태, 2.2는 스테이션 하나를 들여다보는 정도.

세 값 모두 순수 함수 안에서 클램프하므로, 화면 코드가 범위를 몰라도 안전합니다.

## 4. 구조

- `layout.js`
  - `CAMERA.orbit = { yaw: [0, 90], pitch: [15, 80], zoom: [0.85, 2.2] }` 추가.
  - `fitCamera(aspect, opts)`가 `opts.yawDeg`·`opts.pitchDeg`·`opts.zoom`을 받는다. 없으면 지금처럼 방위 프리셋을 쓴다. 각각 위 범위로 클램프하고, 거리 `d`는 재중심까지 끝난 뒤 `d / zoom`으로 조정한다(타깃은 그대로 — 줌인은 자연스럽게 화면을 잘라낸다).
  - 반환값에 `yawDeg`·`pitchDeg`·`zoom`(클램프된 실제 값)을 추가한다. `position`·`target`·`dir`·`fovDeg`·`distance`는 그대로.
  - **인자 없이 부른 결과는 지금과 완전히 같아야 한다**(기존 구도·검증 캡처가 바뀌면 안 된다).
- `lab-room.js`
  - 모듈 상태 `orbit`(초기 `null` = 프리셋 그대로). 첫 조작에서 현재 프리셋 값으로 채운 뒤 갱신한다.
  - `applyCamera()`가 `L.fitCamera(aspect, orbit || {})`를 부른다. 방향이 바뀌면(가로↔세로) `orbit`이 `null`일 때만 새 프리셋을 따르고, 사용자가 돌린 뒤에는 그 각도를 유지한다.
  - 드래그·휠·리셋 핸들러는 모두 `markInput()`을 부르고 `applyCamera()` 뒤에 `renderOnce()`로 저모션 경로를 덮는다.
- `site/labs/index.html`(또는 랩 페이지 CSS): 뷰포트에 `touch-action:none`, 그리고 "drag to look around · double-click to reset" 정도의 짧은 안내 한 줄.

## 5. 테스트
`tools/layout.test.mjs`에 추가:
1. `fitCamera(aspect)`(인자 없음)의 결과가 회귀 없이 유지된다 — 기존 두 테스트가 이미 지키므로, 여기서는 `fitCamera(a, {})`가 `fitCamera(a)`와 같은 값을 내는지만 본다.
2. 클램프: 범위 밖 yaw·pitch·zoom을 넣으면 반환값이 경계로 잘린다.
3. 줌: `zoom`이 커지면 `distance`가 그 배율만큼 정확히 줄고 `target`은 변하지 않는다.
4. 회전해도 다섯 스테이션의 앵커가 모두 화면(NDC [-1,1]) 안에 남는다 — yaw·pitch 범위의 격자점 전부에서(zoom 1 기준).
